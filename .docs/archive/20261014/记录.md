# 2026-10-14 开发记录

## 23:44 剪贴板基座完整性修复（clipboard-rs 迁移收口）
- 目的：把 clipboard-rs 替换后复查发现的缺口全部修掉，让读写、监控、去重与 UI 对截断内容的处理闭环。
- 变更：
  - 截断表示（>2MB 文本/HTML/RTF、>8MB 图片）改用采集时计算的全文 SHA-256 digest 参与去重 hash，同前缀大文本、同尺寸大图、宽高互换大图不再互相去重；digest 存 `payload.extra_json.truncatedDigests`，随回收站往返可复现；无 digest 的旧数据行为不变。
  - 截断图片的 hash 纳入宽高；截断 digest 的旧编码不确定性问题登记为接受风险。
  - 监控读板/写库失败后自动补一次 900ms 单飞重试；重试线程创建失败或状态锁中毒不再让重试永久失效。
  - watcher 接入主动停止（应用退出时 drop shutdown 通道）；退出期 tick 早退；watcher panic 兜底进入 900ms 降级轮询；主动退出不再误写 `MONITOR_WATCHER_UNAVAILABLE`。
  - `self_write_hash` 在观察到其他内容时清除，陈旧标记不再吞掉后续同内容的真实复制。
  - PDF 判定：保留完整数据的 `com.adobe.pdf` flavor → 主类型 `other`，不再保存 NSImage 渲染位图、写回只写 PDF 原表示；>1MB 被截断的 PDF 仍按 `image`（位图是唯一可粘贴表示），保证写回→回读 hash 闭环。
  - 图片写回改为应用自编码 `public.png` + best-effort `public.tiff`，全部走 `Other` 写入；字节长度不符或编码失败返回 `PASTEBOARD_WRITE_FAILED`，不再依赖基座 `set_image` 的静默失败路径，也避免编码器 panic。
  - 截断可见性：`ClipboardItemSummary` 增 `isTruncated`；主列表、网格卡片、浮窗行、回收站行显示「已截断」标记，预览区对所有类型（含图片）显示截断说明。
  - 回收站 `TrashEntry` 增 `isTruncated` 字段；恢复条目保留 `is_truncated` 与真实 `payload_size_bytes`。
  - 浏览器 fallback 数据补 link/other 条目与 flavor；MainApp 事件取消订阅失败不再产生未处理拒绝。
  - 文档同步：`AGENTS.md` 的捕获/写回链路、监控间隔与 DB v5 表述；两份既有计划追加修复指针；新增修复账本。
