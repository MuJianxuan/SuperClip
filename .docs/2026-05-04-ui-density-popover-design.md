# SuperClip UI 密度与 Popover 工具感美化设计

## 背景与证据

当前界面“不够美观”的主要根因不是字体过大，而是窗口尺寸、布局断点和组件密度不一致：

- Rust 运行时 `small_window` 为 `760x560`，且主窗口显示路径默认请求 small mode。
- UI/UX 规范要求标准菜单栏 popover 宽度为 `840 ~ 880px`、最大高度 `640px`，`720 ~ 760px` 只作为紧凑模式。
- React 侧以 `900px` 作为宽布局断点，导致规范推荐的 `840 ~ 880px` 区间仍被当作紧凑布局。
- 历史列表行使用较大的 icon、padding、两行 preview 与 metadata，实际视觉高度超过规范的 `40 ~ 48px` 目标。
- 主界面和设置页存在较多 `16px ~ 24px` 圆角、多层卡片和较厚 padding，使小窗口中内容显得更大。

## 设计目标

- 保持 SuperClip 作为菜单栏 popover 工具的气质：安静、精准、本地可信、键盘优先。
- 默认主界面进入标准双栏布局，而不是一打开就落入紧凑模式。
- 在不牺牲可读性和点击目标的前提下，提高信息密度。
- 主界面与设置页使用一致的尺寸、圆角、间距和语义 token。
- 遵守既有冻结约束：Lucide、Inter/SF Pro fallback、shadcn/ui + Radix + Tailwind、语义 token。

## 范围

本次范围包含：

- 主界面窗口尺寸、布局断点、header、search、history list、detail panel、tools panel、footer。
- 设置页一级信息架构、分组归位、视觉密度。
- 颜色 token 和局部硬编码样式收敛。

本次不包含：

- 新增 P1 设置项，例如 density、row height、hover 强度、缩略图密度。
- 重做后端数据结构。
- 修改 clipboard action 语义。
- 引入新的 UI 库或图标库。

## 主界面设计

### 窗口与断点

- 标准 popover：目标 `860x640`，允许在 `840 ~ 880px` 宽度内保持标准双栏。
- 紧凑 popover：保留 `760x560`，仅作为安全区不足或小屏回退。
- fallback window：沿用同一内容壳体，不切换为另一套临时窗口。
- React 宽布局断点从 `900px` 调整到与标准 popover 一致的阈值，建议 `840px`。

### 线框

```text
主界面 860 x 640
┌────────────────────────────────────────┐
│ SuperClip   [ 搜索剪贴板          ] 状态 │
├──────────────────────────┬─────────────┤
│ 历史                      │ 选中摘要     │
│ ┌ row 44~52px ┐           │ 主动作       │
│ ├ row 44~52px ┤           │ 次级动作     │
│ ├ row 44~52px ┤           │ 工具列表     │
│ └ ...         ┘           │             │
├──────────────────────────┴─────────────┤
│ ↑↓  Enter  Cmd+Enter  Space  Esc        │
└────────────────────────────────────────┘
```

### Header 与 Search

- Header 减少垂直 padding，让搜索框和状态信息占用更少高度。
- 搜索框高度从偏大的 `44px` 收敛到约 `38 ~ 40px`。
- 保留快捷键提示，但弱化为更轻的 pill 或右侧状态文本，避免挤压搜索输入。
- 不引入营销式标题区，保持工具感。

### 历史列表

- 目标视觉行高：`44 ~ 52px`。
- 图标容器从 `36px` 收敛到约 `30 ~ 32px`。
- 行内 padding、gap 和 metadata 间距统一收紧。
- 标题保持 `13px`，预览保持 `12px`，不通过大幅缩小字体解决密度问题。
- 选中态保留左侧强调线，但减少阴影和大圆角。

### 右侧详情与工具区

- 右侧宽度在标准模式保持约 `300 ~ 320px`，紧凑模式约 `270 ~ 280px`。
- 详情卡片圆角收敛到 `12px`，内部元素使用 `10px`，按钮使用 `8px`。
- 主动作按钮保持显著，但高度收敛到 `32 ~ 34px`。
- 工具区补齐规范项：设置、暂停/恢复监听、清空历史、权限、诊断、关于、退出。
- 紧凑模式不使用过扁的 58px 图标 dock；应保留可理解的工具列表或分组入口。

### Footer

- Footer 从多个厚 pill 收敛为更轻的键盘提示条。
- 保留 `↑↓`、`Enter`、`Cmd+Enter`、`Space`、`Esc`，但降低视觉重量。

## 设置页设计

### 信息架构

设置页一级导航恢复为：

```text
通用
快捷键
粘贴行为
隐私与排除规则
外观
启动与更新
关于
```

字段归位：

- 通用：历史保留数量、置顶提醒等基础行为。
- 快捷键：当前绑定、重新录入、恢复默认、冲突提示。
- 粘贴行为：默认动作，即“直接粘贴优先 / 仅复制优先”。
- 隐私与排除规则：App Bundle ID、内容类型、关键词规则。
- 外观：主题模式。
- 启动与更新：登录启动、启动时自动显示、版本与恢复说明。
- 关于：版本、诊断导出、项目信息。

### 线框

```text
设置页
┌──────────┬─────────────────────────────┐
│ 通用     │ 当前分组标题                 │
│ 快捷键   │ ┌ 设置项 row ┐               │
│ 粘贴行为 │ ├ 设置项 row ┤               │
│ 隐私规则 │ └ 设置项 row ┘               │
│ 外观     │                             │
│ 启动更新 │                             │
│ 关于     │                             │
└──────────┴─────────────────────────────┘
```

### 视觉密度

- 侧边栏宽度保持紧凑，减少大面积空白。
- Section card 使用 `12px` 圆角，Row 使用 `10px` 圆角。
- 减少设置项内部 `px-4 py-4` 这类大块 spacing。
- 表单行保留足够点击目标，避免压缩到难以操作。

## 颜色与视觉 token

- Light 模式向 neutral 灰白回归，减少暖米色和绿色 accent 的强风格感。
- 保留低饱和 success/warning/danger。
- 优先使用 `var(--*)` 语义 token，减少 `bg-white`、硬编码 rgba 阴影和渐变。
- Dark/system 模式保持同一语义映射，避免组件局部漂移。

## 测试与验收

最低验收：

- `860x640` 下主界面进入标准双栏，历史列表首屏容量明显增加。
- `760x560` 下紧凑布局不遮挡搜索框、主动作、权限状态。
- 历史列表行不再显得臃肿，信息仍可读。
- 设置页显示 7 个一级导航，字段归位正确。
- Light/dark/system 三种主题下可读性正常。
- `npm run build` 通过。
- 若运行 Tauri 验证，启动服务前先确认端口与已有进程状态。

## 实施建议

建议按以下顺序实现：

1. 统一窗口尺寸与 React 断点。
2. 收敛主界面 header、history row、detail/tools、footer 密度。
3. 恢复设置页 IA 并移动字段。
4. 收敛颜色 token 与硬编码样式。
5. 构建验证，并在必要时做桌面窗口截图检查。
