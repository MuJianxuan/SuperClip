## 问题与机会

### 痛点（用户原话）

> 「现在鼠标移动上去就会显示悬浮预览，我想改成不要悬浮，设计另外一种显示方式，我感觉可以右边弹出侧边栏这种，可以滚动的方式显示，需要考虑不同类型的情况」

用户确认的根因（Q1，2026-10-20）：**弹窗时机不可控**，且**内容看不清**。两条同时成立，因此正确解法不是「换个位置弹窗」，而是「触发从 hover 改为显式选择 + 展示从浮窗改为固定区域」。

### 目标用户与角色

- 使用者：当前为单一用户（工具作者本人），重度开发者，用剪贴板历史扫读并取回内容。
- 角色区分：无多角色、无权限分级。

### 触发场景

在主窗浏览/搜索剪贴板历史时，需要「确认这条到底写了什么」再决定粘贴、置顶或删除。频率：日常高频（每次取回历史内容都会发生）。

### 现有做法与代价

- 现有做法：鼠标滑过行 → 浮窗弹出 → 移进浮窗才能读全文 → 移开即消失。
- 代价：①路过行就弹，干扰扫读；②浮窗跟鼠标走，位置不稳定；③320×360 太小，长文本/代码被挤；④为可用性付出轮询与兜底逻辑（约 150 行前端容错代码 + 两个 Rust 命令的调用点）。

## 目标与非目标

### 目标

- 主窗去掉 hover 触发预览，改为选中驱动，右侧固定区域展示。
- 分类型展示（text / html / rtf / image / file / link / other）。
- dock 可折叠、宽度可拖拽并记忆；窄窗自动覆盖式。
- 键盘导航（↑↓）与选中同步刷新 dock。

### 约束

- 只使用主窗内部能力：不新增窗口、不新增 Rust command、不改 IPC 契约、不改 DB schema。
- 主窗尺寸保持 900×620（min 820×520）不变，方案必须在固定窗口尺寸下可用。
- 前端测试（vitest）需同步更新；不引入新的 UI 依赖库。

### 非目标

- 不改 popup / quick_panel 的 hover 预览（用户明确保留）。
- 不新增 Rust command、不改数据库 schema、不改 IPC 契约。
- HTML/RTF **不做渲染视图**，只做源码视图（渲染需 sandbox，成本与安全风险另议）。
- 不做「关闭自动显示」的设置项（用户确认按推荐，选中即预览为唯一主路径）。
- 不做内联展开（方向 B）、底部抽屉（方向 C）、保留浮窗的显式触发（方向 D）。
- 不顺手删除 Rust 侧 preview 窗口与命令（popup 仍依赖）；前端 hover 链路的清理属于跟随清理，需另行确认。

## 推荐方案

### 核心用户流程

```text
鼠标扫过列表 → 仅行高亮（无浮窗、无轮询）
单击行 A     → 右侧 dock 显示 A（先骨架，detail 到达后填充）
↑ / ↓       → 选中移动，dock 同步切换，列表自动滚到选中项
双击 / ↵    → 粘贴（原行为不变）
⌘\          → dock 折叠 / 展开（状态记忆）
窗口 < 960px → dock 自动切覆盖式（浮在列表上，不压缩列表；Esc 或点击外部关闭）
多选 ≥2 项   → dock 显示批量摘要（已选 N 项），不显示单条
回收站 / 设置/排除规则 → dock 隐藏
```

### 功能点（含关键边界行为）

| 功能点 | 行为 |
| --- | --- |
| 触发 | 单击行、键盘 ↑↓ 选中；**hover 绝不触发展示** |
| 摆放 | ≥960px：常驻 dock（宽度默认约 300–320px，可拖拽并记忆）；<960px：覆盖式 |
| text | 标题 + 全文（可滚动，``` 代码块等宽）+ 字符数 |
| html / rtf | 与 text 相同，源码视图（无渲染视图） |
| image | 自适应大图（宽度撑满 dock）+ 像素尺寸 + 体积 |
| file | 多文件清单（文件名 + 路径，可滚动）；不做缩略图 |
| link | 标题 + 完整 URL（可选中复制）+ 域名 |
| other | 「该类型仅支持复制」说明 + flavor 清单 |
| 空态 | 未选中时显示「选择一条记录查看内容」；**不自动选第一行** |
| 选中项消失 | 切换类型 chip / 侧栏 / 搜索导致选中项不在结果集内时，dock 回到空态 |
| 加载态 | 切换条目先显示骨架，避免旧内容残留造成串条 |
| 滚动 | dock 内部独立滚动，不带动列表 |
| 折叠 | `⌘\` 或头部按钮；折叠后列表恢复全宽（快捷键取值见「开放问题」，待最终确认） |
| 多选 | ≥2 项时显示批量摘要与批量可用动作，不显示单条预览 |
| 非列表视图 | 回收站、设置、排除规则下 dock 不渲染 |

### 与现有功能的关系

- 复用 `PreviewApp` 的内容渲染逻辑（抽为共享 `PreviewContent` 组件），popup 的 hover 预览**保持不变**，继续走现有 `preview:show` 链路。
- 复用 `clipboardGet` 详情加载、`onSelect` 选中态、kind 元数据与主题变量。
- 主窗 hover 链路可整条移除：`useHoverPreview` 调用点、`previewShow`/`previewHide` 调用、`preview:mouse-enter/leave` 监听、300ms 鼠标位置轮询（约 150 行）。Rust 侧保持不动，popup 仍使用。

### 设计理由

1. 触发可预测：只有显式选择才改变预览内容，扫读列表不再被打断。
2. 空间更大：dock 常驻时可用宽度约 300–320px，且高度撑满窗口（对比 320×360 浮窗）。
3. 边界清晰：鼠标位置与预览显示彻底解耦，删除轮询与跨窗口竞态处理。
4. 与键盘导航天然一致：选中即预览，↑↓ 浏览时预览连续刷新。

### 与业界做法的异同

- 同：选中驱动的 master-detail（CopyQ、Paste）、可折叠面板 + 快捷键（Maccy）。
- 异：本方案额外加「窄窗自动覆盖式」与「按类型定制布局」——因为主窗尺寸固定且偏小（900×620），Maccy/Paste 的窗口形态无需此约束。

> 仅方向层；表结构与 API 定义留给实施阶段。

| 类别 | 内容 |
| --- | --- |
| 可复用既有能力 | `clipboardGet` 详情加载；`PreviewApp` 渲染逻辑（类型标签、代码块、图片、flavor 清单、元信息胶囊）；`KIND_META`；主题 CSS 变量；`onSelect` 选中态 |
| 需要新增 | `MainPreviewDock` 组件；共享 `PreviewContent` 渲染模块；dock 宽度与折叠状态（localStorage 持久化）；≥960 / <960 响应式布局切换；折叠快捷键；多选摘要态与加载骨架 |
| 数据来源 | 前端 `clipboardGet(id)`（现有 command），选中变化即拉取；列表摘要数据来自现有 `useClipboardData` |
| 外部依赖与集成 | 无新增依赖、无新增 IPC、无 schema 变更；主窗布局改为 list + dock 的双列容器 |
| 影响面 | `src/windows/main/MainApp.tsx`（布局与状态机）、`MainListView.tsx` / `MainGridView.tsx`（去掉 hover 回调）、`src/preview/PreviewApp.tsx`（抽取渲染）、新增 dock 组件；对应前端测试更新 |
| 主要风险 | ①列表收窄后标题截断增多 ②多选/批量选择与 dock 状态机冲突 ③键盘导航与滚动联动 ④grid 视图需与 list 对齐同一套逻辑 ⑤快速切换选中时的详情串条 |

## 开放问题与假设

### 已确认（用户明确表述）

- 采用方向 A（2026-10-20）。
- 自动显示默认开启，「选中即预览」为唯一主路径，不做关闭开关（用户「按推荐」）。
- 常驻/覆盖断点 960px（用户「可以」）。
- HTML/RTF 只做源码视图（用户「确认」）。
- popup / 快捷面板的 hover 预览保留不改（Q5 推荐，用户「都按推荐」）。
- 空态不自动选第一行；多选时显示批量摘要；回收站/设置视图不显示 dock（Q6 推荐，用户「都按推荐」）。
- 成功判据 S-01~S-05（Q7 推荐，用户「都按推荐」）。
