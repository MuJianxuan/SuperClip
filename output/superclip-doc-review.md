## 1. 执行摘要

### 总体判断
当前三份文档已经从“方向正确的方案包”提升为“接近可拆 Spec 的实现前文档包”。
此前常见的关键缺口——如 IPC 契约、Tauri capability / permission、性能预算、无障碍要求、设置字段级约束——在新版本里已经明显补强。

当前最有价值的地方，是三文档已经共同围绕同一条主闭环组织：

**复制 -> 入库 -> 唤起 -> 搜索 -> 选中 -> 执行动作（直接粘贴 / 仅复制） -> 失败回退 -> 状态提示**

这意味着：
- 产品主路径已经比较完整；
- 技术实现主线已经可落；
- UI/UX 也已经有冻结约束，不会轻易跑偏成 AI 模板化页面。

但它们还没有完全达到“无歧义进入编码”的程度。当前仍有 4 个高优先级缺口：
1. **置顶能力的契约未打通**：PRD 有“置顶”，UI 有置顶展示，但 Architecture 缺 pin/unpin 命令与事件。
2. **诊断导出契约缺失**：PRD 与 UIUX 都提到诊断导出，但 Architecture 没有对应 command / payload / 文件格式约定。
3. **恢复模式与恢复中状态混用**：PRD / Architecture 要求迁移失败后进入只读可浏览模式，但 UIUX 只定义了“全局遮罩、仅观察”的阻塞态。
4. **直接粘贴支持矩阵未明确定义**：文档没有写清 text / html / rtf / image / file 各自是否支持 direct paste，还是部分类型只能 copy-only。

## 3. 分文档评分

### 3.1 PRD 评分：**90 / 100**

#### 优点
1. **产品边界控制很好**：本地、macOS arm、不开云、菜单栏优先，方向清晰。
2. **核心闭环完整**：监听、搜索、预览、复制 / 粘贴、失败回退、权限降级都已定义。
3. **设置与规则模型有实用深度**：默认值、建议范围、冲突检测、排除规则分类都已落到字段层。
4. **非功能要求已进入 PRD**：性能预算、冷启动、CPU、内存、数据库迁移失败策略都被写入。
5. **隐私意识到位**：明确默认不联网、不做 OCR、不上传内容。

#### 问题
1. **置顶能力只有产品定义，没有操作契约追踪点**：未明确用户如何 pin/unpin、是否支持批量、是否有上限。
2. **诊断导出是需求，但缺少“导出什么、导出到哪里、格式是什么”的定义。**
3. **直接粘贴支持矩阵未写清**：文件、富文本、图片是否都支持 direct paste，还是只支持 copy-only，用户预期边界还不够稳。
4. **恢复模式的用户体验还不够精确**：迁移失败后“只读可浏览”是需求，但对应 UI 状态没有完全闭环。

#### 结论
PRD 已经不仅能做方向评审，也能支撑较细的 Spec 拆解；剩下的问题主要是与 Architecture / UIUX 的贯通程度，而不是 PRD 自身太空。

---

### 3.2 Architecture 评分：**88 / 100**

#### 优点
1. **技术栈与职责切分成熟**：Tauri 2 + Rust + React + SQLite 的职责边界清晰。
2. **IPC 契约已经补齐大半**：commands / events / windows / payload 约定完整度明显提升。
3. **数据模型具备工程可操作性**：主表、payload 表、settings、exclusion rules、FTS 索引都具备落地形态。
4. **能力与权限意识到位**：capability / permission、global-shortcut、positioner、shell/open-system-settings 都已被纳入考虑。
5. **恢复、降级、错误分类比普通文档成熟**：不是只有 happy path，而是明确考虑了恢复模式、DB 锁、权限缺失、paste 失败。

#### 问题
1. **缺少置顶能力的 IPC 契约**：没有 `clipboard:pin` / `clipboard:unpin` / `clipboard:update-meta` 之类的命令，也没有对应刷新事件。
2. **缺少诊断导出契约**：没有 `diagnostics:export` 或等价 command，也没有导出数据结构约定。
3. **直接粘贴支持矩阵未写清**：Architecture 描述了通用时序，但没有给出不同内容类型的策略分层。
4. **部分验收指标未完全继承 PRD**：例如 PRD 的“常驻内存 < 220MB”“回退提示 1 秒内完成”，Architecture 未显式继承。
5. **登录启动、Dock 图标弱化 / 隐藏的技术策略仍偏原则化**：缺少宿主级实现说明或限制说明。

#### 结论
Architecture 已经从“方案说明书”升级到“接近实现蓝图”，但还差少量关键 command / capability / support matrix 才能进入无歧义拆任务。

---

### 3.3 UIUX 评分：**85 / 100**

#### 优点
1. **UI 工具链冻结明确**：Lucide、Inter、shadcn/ui、Radix、Tailwind、语义 token 已锁定。
2. **页面骨架明确且与 PRD 高度一致**：tray popover、settings、permission guide 都有对应界面载体。
3. **交互规则继承充分**：键盘操作、toast 回退、状态展示、内容预览都能直接指导实现。
4. **无障碍与微文案要求已进入规范**：相比很多 UI 文档，这部分完成度较高。
5. **明确规避 AI 模板化反模式**：无 emoji、无紫粉渐变、无系统字体直出、无卡片墙。

#### 问题
1. **置顶能力缺少可见操作入口**：有“置顶项展示规则”，但没有写清 pin/unpin 的按钮、快捷操作或菜单入口。
2. **恢复模式 UI 没有和 Architecture 对齐**：现在只有“恢复中 / 迁移中”的阻塞遮罩，没有“迁移失败后的只读恢复模式”界面。
3. **深色主题 token 仍偏抽象**：虽然定义了 `light / dark / system`，但深色 token 映射值与组件级落点还不够细。
4. **破坏性操作确认规则不够细**：清空历史、删除单条、关闭引导是否需要 confirm，尚未写清。
5. **窄屏 / 小屏 / 刘海区安全边界规则不足**：popover 宽度较明确，但极端窗口布局缺少降级规则。

#### 结论
UIUX 已能稳定锁定方向并支持中高保真实现，但若要直接交给前端编码，仍建议先补 pin/unpin、recovery mode、dark token mapping 三个点。

## 4. 跨文档一致性审查

### 4.1 一致性较强的部分

1. **产品定位一致**：三文档都强调“本地优先、不开云、稳定优先”。
2. **入口模型一致**：菜单栏图标 + 全局快捷键。
3. **动作模型一致**：直接粘贴 / 仅复制双路径，且有失败回退。
4. **权限降级一致**：无 Accessibility 时仍可浏览 / 搜索 / 复制，只禁 direct paste。
5. **主界面骨架一致**：左侧历史列表，右侧摘要 + 功能列表。
6. **设计体系一致**：Lucide + Inter + shadcn/ui + Tailwind + 语义 token。
7. **状态意识一致**：暂停监听、无结果、权限缺失、写入中、迁移中等都有表达。
8. **恢复与可靠性意识一致**：不是只做单次成功路径，而是明确考虑恢复模式与失败分类。

### 4.2 关键断点

1. **置顶能力跨文档未闭环**
   - PRD：明确要求支持“置顶”。
   - UIUX：定义了置顶项展示规则。
   - Architecture：缺少 pin/unpin command / event。

2. **诊断导出跨文档未闭环**
   - PRD：有诊断开关、导出最近错误与迁移状态。
   - UIUX：设置窗口 About 中有诊断导出入口。
   - Architecture：没有导出接口与数据模型。

3. **恢复模式定义不一致**
   - PRD / Architecture：迁移失败后进入只读可浏览恢复模式。
   - UIUX：只有“恢复中 / 迁移中”的阻塞遮罩，没有“恢复模式”页面或只读状态条。

4. **直接粘贴类型边界不够明确**
   - 三文档都承认 direct paste 很重要。
   - 但三文档都没有明确列出：哪些内容类型支持 direct paste，哪些只支持 copy-only。

5. **部分非功能指标没有完全互相继承**
   - PRD 有更细的内存与时延阈值。
   - Architecture 没完全同步全部指标。
   - UIUX 也没有把这些性能感知要求映射到界面反馈策略。

## 6. 关键风险与阻塞项

以下问题建议在进入 Spec 前解决，否则 tasks 拆解和编码阶段会反复回头补文档。

### 阻塞项 1：置顶能力缺少完整契约
建议补齐：
- command：`clipboard:pin` / `clipboard:unpin` 或 `clipboard:update-meta`
- event：`item-updated` 或等价事件
- UI：pin/unpin 操作入口（行内按钮、右键菜单、快捷键三选一或组合）
- 数据：是否需要 `pinned_at` 或排序字段

### 阻塞项 2：诊断导出能力没有架构闭环
建议补齐：
- command：`diagnostics:export`
- 导出内容：最近错误、迁移状态、版本信息、数据库健康摘要、权限状态
- 导出格式：如 `.json` 或 `.zip`
- UI：入口、成功 / 失败 toast、隐私提醒

### 阻塞项 3：恢复模式与恢复中状态要拆开
建议拆成两个概念：
1. **恢复中 / 迁移中**：阻塞态，可用全局遮罩
2. **恢复模式（只读）**：非阻塞态，可浏览 / 搜索 / 复制 / 导出诊断，但禁 direct paste 与写操作

### 阻塞项 4：直接粘贴支持矩阵需要白纸黑字写清
建议补一张表：
- text：支持 direct paste
- html / rtf：是否支持 direct paste，失败如何回退
- image：哪些 App 目标可工作，默认策略是什么
- file：是否只允许 copy-only，还是允许 pasteboard file URL paste
- unsupported：统一降级 copy-only + 用户提示

### 高优先级项 5：主题 token 需要从“语义层”再落到“组件层”
建议补充：
- light / dark 两套实际 token 映射
- banner / toast / input / selected row / sidebar / preview panel 的语义映射
- 跟随系统切换时的过渡策略

### 高优先级项 6：把 PRD 非功能指标完整继承到 Architecture
至少补齐：
- 常驻内存 `< 220MB`
- direct paste 失败回退提示 `< 1s`
- 数据库恢复模式的可交互范围
