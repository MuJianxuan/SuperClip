# SuperClip UI / UX 规范（P0修订版）

## 气质关键词
- 安静
- 精准
- 高级灰白
- 本地可信
- 键盘优先

## 冻结约束
- **图标库**：Lucide
- **字体系统**：Inter + SF Pro fallback，等宽内容用 SF Mono / ui-monospace
- **设计 token**：只用语义 token，不直接硬编码紫粉渐变
- **组件生态**：shadcn/ui + Radix + Tailwind
- **页面骨架**：菜单栏 popover + 设置窗口 + 权限引导

## 颜色 token
- bg: neutral-50
- surface: white
- surface-2: neutral-100
- border: neutral-200
- text-primary: neutral-900
- text-secondary: neutral-600
- text-tertiary: neutral-500
- accent: neutral-900
- accent-soft: neutral-200
- success / warning / danger：低饱和语义色

## 主题模式
- **light**：默认模式，保持高级灰白。
- **dark**：用于夜间 / 低光环境，保持低饱和、低对比刺眼。
- **system**：跟随系统外观设置。
- 三种模式共用同一套语义 token，不直接在组件内写死颜色值。

## 组件级主题映射
- `tray-popover`：light 用 `surface + border`；dark 用深灰表面层与低对比描边，保持菜单栏工具感而非沉浸式全黑面板。
- 历史列表选中态：light 用 `accent-soft` + 左侧强调线；dark 用低亮度强调底 + 同色系强调线，不用高饱和蓝紫。
- banner / toast：success / warning / danger 都走低饱和语义色，在 dark 下优先提高边框与文字对比度，不靠纯背景块。
- 输入框、搜索框、设置表单项必须沿用同一套 light / dark 语义映射，不能单独漂移成系统默认样式。

## 排版 token
- 基础字体：Inter
- macOS 回退：SF Pro Text / SF Pro Display
- 标题：14 / 16 / 20 / 24
- 正文：13 / 14
- 辅助信息：11 / 12
- 等宽：12 / 13

## 空间与形状
- 圆角：12px 主卡片，10px 次级卡片，8px 按钮
- 间距：8pt 网格
- 阴影：极轻，优先边框和层级，不用重投影
- 列表行高：40 ~ 48px

## 页面骨架
### 1. 菜单栏 popover（默认主界面）
- 单一菜单栏图标承载两个菜单组，不拆成两个独立图标
- 左侧：粘贴记录列表
- 右侧：选中项摘要 + 功能列表
- 顶部：搜索框、监听状态、权限状态
- 底部：快捷操作提示

### 2. 设置窗口
- 通用
- 快捷键
- 粘贴行为
- 隐私 / 排除规则
- 外观
- 启动与更新
- 关于

### 设置窗口字段级约束
- **通用**：启动时自动显示、默认动作、历史保留数量。
- **快捷键**：当前绑定、冲突提示、重新录入、恢复默认。
- **粘贴行为**：直接粘贴优先 / 仅复制优先、失败回退、粘贴后恢复剪贴板的延迟。
- **隐私 / 排除规则**：按 App Bundle ID、内容类型、关键词三类编辑；支持启用 / 禁用与一键清空。
- **外观**：theme、density、row height、hover 强度、缩略图密度。
- **启动与更新**：登录启动、版本信息、崩溃恢复说明。
- **关于**：版本号、开源入口、诊断导出入口。
- **启动与更新补充**：登录启动开关失败时，原位展示 inline error + Retry，不跳转、不弹系统级阻断框。

### 3. 权限引导层
- Accessibility 检查
- 一键打开系统设置
- 直接粘贴降级说明

## 菜单栏 popover 版式
- 建议宽度：840 ~ 880px
- 建议最大高度：640px
- 左右两栏固定分区，内容不足时保持留白层级
- 任何列表超长都在各自栏内滚动，避免整个 popover 失控
- 打开后默认焦点在搜索框；若有历史项，第一条同时高亮

## 紧凑模式与回退窗口规则
- 当安全区不足以容纳标准 840px 双栏布局时，进入 720 ~ 760px 的紧凑模式。
- 紧凑模式下仍保留双栏，但右侧摘要默认折叠为较短预览，功能列表保持可见，不允许把关键动作藏到二级路径。
- 若刘海区、菜单栏安全区或屏幕边缘仍导致裁切风险，则回退为当前显示器上的居中工具窗口。
- 回退窗口沿用同一视觉语言与组件系统，不能切成另一套“临时系统弹窗”样式。
- 无论标准模式、紧凑模式还是回退窗口，搜索框、权限状态、默认动作按钮都必须首屏可见。

## 多显示器与刘海区体验规则
- 菜单栏点击时，界面应跟随点击所在显示器的菜单栏出现。
- 全局快捷键唤起时，界面优先跟随当前焦点应用所在显示器。
- 界面不得压到刘海区下缘；顶部搜索框、状态 pill、关闭路径不能被遮挡。
- 若发生定位回退，toast 或轻量提示需说明“已切换为居中窗口显示”，但不应打断用户继续搜索。

## 左侧：粘贴记录列表
- 文本：两行摘要 + 来源 / 时间
- 图片：缩略图 + 尺寸
- 文件：文件名 + 数量 + 路径摘要
- 富文本：标签 + 纯文本摘要
- 置顶项：固定在顶部，不用 emoji 标识
- 每行在 hover / focus 态显示 Pin / Unpin 图标按钮；同时保留右键菜单入口，避免只靠 hover 发现。
- 选中态：浅底色 + 左侧强调线

## 右侧：选中项摘要 + 功能列表
### 选中项摘要
- 标题
- 来源应用
- 时间
- 预览内容
- 次级动作：Pin / Unpin、仅复制、查看详情
- 支持快捷键提示

### 功能列表（固定）
- 设置
- 暂停 / 恢复监听
- 清空历史
- 权限状态 / 打开系统设置
- 导出诊断
- 登录时启动
- 关于
- 退出

## 交互规则
- `Enter`：执行默认动作（直接粘贴 / 仅复制，按设置切换）
- `Cmd+Enter`：执行相反动作
- `↑ / ↓`：切换历史项
- `Space`：展开 / 收起摘要
- `Delete / Backspace`：删除当前高亮项（搜索框内仍是文本编辑）
- `Esc`：关闭面板
- 直接粘贴失败后：toast 提示 + 自动回退为仅复制
- 删除单条后：toast 提示可撤销，默认保留 30 秒撤销窗口。

## 动作可用性矩阵（按内容类型）
| 内容类型 | 主按钮 | 次级按钮 | 禁用说明 |
|---|---|---|---|
| Text | 直接粘贴 / 仅复制 | Pin / Delete | 无 |
| HTML / RTF | 直接粘贴 / 仅复制 | Pin / Delete | 若目标应用不支持富文本，toast 说明已退化为纯文本或仅复制 |
| Image | 直接粘贴 / 仅复制 | Pin / Delete | 若目标应用不接受图片 pasteboard，toast 说明已回退为仅复制 |
| File | 仅复制 | Pin / Delete | 主按钮直接显示“仅复制”，并给 tooltip 说明 P0 不承诺 direct paste |
| Truncated / Unsupported | 查看摘要 / 仅复制摘要 | 查看详情 | 明确提示“当前项不支持直接粘贴” |

## 内容预览规则
- 文本默认展示两行，超长后折叠并显示“展开”。
- 图片默认展示缩略图与尺寸，点击后放大到右侧摘要区。
- 文件默认展示文件名、数量、来源路径摘要；超过 5 个文件时显示聚合数量。
- HTML / RTF 默认只渲染纯文本摘要，不直接渲染不可信 HTML。
- 被截断的大内容必须显示截断徽标，避免误以为完整可用。

## 无障碍要求
- 所有可点击项必须有明确文字标签，不能只靠颜色或图标区分。
- 焦点顺序必须符合视觉顺序，搜索框优先。
- 焦点高亮不可被完全移除。
- 对比度需满足可读性要求，避免浅灰字压浅灰底。
- 尊重系统 reduced motion，避免大范围弹跳动效。

## 微文案规则
- banner、toast、empty state、confirm modal 的文案都必须说明“发生了什么 + 该怎么做”。
- 错误文案避免技术黑话，默认给用户一个下一步动作。
- 权限提示优先说明“为什么需要”与“不会做什么”。
- 直接粘贴失败文案必须明确写出已回退为仅复制。
- 恢复模式文案必须明确写出“当前为只读模式，不会修改数据库，可继续浏览 / 搜索 / 复制 / 导出诊断”。
- 删除成功 toast 必须包含“撤销”动作和剩余时间。
- 诊断导出取消时不显示错误 toast，只关闭保存流程。
- 登录启动开关失败时，文案必须说明“未能更新开机启动设置，应用仍可正常使用”。
- 定位回退提示必须说明“当前菜单栏区域无法完整展示，已切换为居中窗口”。

## 破坏性操作确认规则
- 删除单条：默认不弹 confirm modal，执行后提供带撤销入口的 toast；超时后不可恢复。
- 清空历史：必须二次确认，文案明确说明“不会清除系统当前剪贴板内容”。
- 在恢复模式下，所有破坏性按钮都展示为 disabled，并附带只读说明。

## 状态设计
| 状态 | 展示方式 | 可执行动作 | 是否阻塞主流程 |
|---|---|---|---|
| 正常监听 | 状态 pill | 搜索、粘贴、删除 | 否 |
| 已暂停 | 顶部 banner + pill | 恢复监听 | 否 |
| 无历史 | 空状态 | 继续复制 | 否 |
| 搜索无结果 | 空状态 | 清空搜索 | 否 |
| 权限缺失 | 顶部 banner | 打开系统设置 | 仅阻断直接粘贴 |
| 写入中 / 索引更新中 | 轻量 badge | 继续浏览 | 否 |
| 数据写入失败 | inline error + toast | 重试 | 否 |
| 直接粘贴失败 | toast | 自动回退为仅复制 | 否 |
| 恢复中 / 迁移中 | 全局遮罩 | 仅观察状态 | 是 |
| 恢复模式（只读） | 顶部 warning banner + 只读状态条 | 浏览、搜索、仅复制、导出诊断 | 否 |

## 视觉禁令
- 禁止 emoji 图标
- 禁止紫 / 粉主渐变
- 禁止无层级卡片墙
- 禁止默认系统字体直出
- 禁止“数据库同步中”这类与本地产品不一致的文案

## 视觉总结
- 整体偏克制、留白轻、边框清晰
- 以灰白层级建立信息密度，而不是靠强阴影或高饱和色
- 所有功能态都必须有明确文案或 badge，避免“看起来像空白区域”
- 主题与组件状态都必须能在浅色 / 深色下保持一致的层级感
